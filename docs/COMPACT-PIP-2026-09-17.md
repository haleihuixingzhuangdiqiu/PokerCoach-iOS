# 0.1.14 紧凑悬浮条验收

内容从三行 360×104 改为单行 320×64，例如 `加至 7.40  独赢≈58%`。这些是视频内容尺寸，不是承诺系统窗口的实际物理尺寸；系统画中画的大小、位置与控制按钮仍由 iOS 管理。

- 去掉「建议：」、牌型、策略理由及重复状态说明，主 App 保留详情。
- `跟 3.20` 表示追加 3.20；`加至 8.20` 仍表示本街总投入 8.20。
- 独赢估计仍排除平分；未从概率区间取中点。只有随机范围估计时明确显示 `随机≤7对手` 等条件，不制造行动指令。
- 读不清、遮挡、断流、过期分别短化；过期和断流撤下旧动作与概率。
- 原有时效和 PiP 启停逻辑不变；缓存使用实际可见文字，后台原因更新不会造成重复切换。

## 已完成

1. iPhone 17 Pro 模拟器、iOS 26.5，现有 XCTest 首页和帮助页两项测试最终 **2/2 通过**，无滚动读取金额解释；人工检查原始首页、帮助页截图。
2. 原生 `AVSampleBufferDisplayLayer` 探针覆盖 11 个检查点：内嵌、尝试悬浮、返回、跟注、弃牌、过牌、长金额、未读清、断流、随机条件估计和过期。全部生成帧有 IOSurface，显示缓冲可读取，生成与实际显示像素相符；长金额 `10000000.00` 视觉检查完整。
3. 本轮模拟器不支持系统 PiP，检查以 `--renderer-only` 模式执行并明确排除系统悬浮生命周期验证，不能把尝试悬浮检查点当作真机成功。
4. UI 验收发现首页父子按钮重复使用 `capture.start`，导致 XCTest 定位不唯一；去除隐藏内部按钮标识、保留唯一容器标识，新增唯一性断言。修复后两项 UI 测试均通过。没有更改 ReplayKit 的原生按钮激活事件。

本地 XCTest 结果、原始截图、渲染帧、日志均保留在本机工作目录，不上传设备材料。为保留此前间歇断流证据，本轮没有清空原日志或 App 数据。
