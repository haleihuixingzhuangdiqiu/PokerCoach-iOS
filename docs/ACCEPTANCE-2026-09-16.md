# 0.1.13 研究与验收记录

日期：2026-09-16。结论按规则正确性、录像覆盖、合成策略对照与手机运行分别报告。

## 本轮实际修改

1. 补上本人座位的 `Straddle` 标签区域，覆盖录像中蓝紫色渐变；仍要求明确文字识别，不能把下注 1 当成第三盲。
2. 已有可信开局的同街多人纯跟注/弃牌间隔可以恢复；金额、筹码、底池、行动顺序与加注权仍逐项验证。退款、跨街或未穷尽搜索不直接放行。
3. 修复未来河牌中部分私人坚果牌仍被行为模型模拟弃牌的问题。保护条件包括特定 Broadway、私人 A 高同花、四条和皇家同花顺；只用本人的牌和已公开河牌，是经过验证的充分条件，不是完整坚果分类器。
4. 扩展独立规则检查、固定对手对照和手机组件验收工具。回放先识别操作按钮再检查牌面，失败帧也进入观察分母，错误时撤回结果，缓存建议单独标记。

这里“坚果牌”指在已知本人底牌和河牌下，没有任何合法对手底牌能形成更强牌，仍可能平分。它不是“独赢率必然 100%”。

## 正确性证据

- 本地完整 Swift 回归：**329 项通过、0 失败**，包含持有的私人截图用例。
- 不带私人素材的公开导出副本：**281 项通过、48 项跳过、0 失败**（共 329 项）。发布检查曾发现新增用例把缺素材的跳过异常放进断言而误报失败，已拆开读取与断言并完整重跑；跳过仍不计作识别通过。
- 多人被动行动恢复：11 项新增测试；相关 36 项定向测试全部通过。`tools/audit_recovery_pokerkit.py` 的 10 组独立 PokerKit 0.7.4 对照通过。
- 私人河牌坚果：5 项新增测试，相关 21 项定向测试全部通过；另用 `tools/audit_river_nuts_pokerkit.py` 对 12 个正反例各枚举 990 种合法对手底牌，结果一致。Swift 测试内的穷举使用本项目 evaluator，不能将它本身称为独立裁判。
- iOS Release **0.1.13 / build 14** 构建和主 App／录屏扩展深度签名校验通过。测试 iPhone 当前不可用，尚未覆盖安装此版本，也未完成此版本的手机组件或连续 ReplayKit/PiP 验收。

## 整段录像结构验收

使用本地保留的 240 帧、2 fps 录像抽帧。旧版和新版都用修正后的同一套回放工具，先检查操作控件，再检查牌面，避免漏掉识别失败的操作帧。输出明确标记 `notRealtime=true`。

| 同一录像、同一口径 | 旧版 | 0.1.13 |
| --- | ---: | ---: |
| 抽帧数量 | 240 | 240 |
| 识别到本人操作控件的帧 | 44 | 44 |
| 完整策略有可显示建议的帧 | 7 | 28 |
| 连续操作窗口至少一次有完整建议 | 3 / 11 | 10 / 11 |

44 个操作帧中有 5 帧因飞牌、发牌或公共牌未读全而失败。旧工具在这些检查后才统计操作，曾把分母写成 39；新结果纠正了这一遗漏。窗口按相邻的操作帧归并，不是独立手牌数，也不是经过人工标注的全部真实机会。原录像文件当前不可访问，本轮使用的是保留抽帧，没有验证未被抽到的动态画面。

QQ 翻前剩余窗口包含 0185、0186：第一帧被空公共牌区校验拦住，第二帧处于确认中，因此仍未产出完整建议。不能把它说成游戏只给了一帧时间。录像中的 QQ 全下场景也不是用户口述“有人下注 4 元”的同一输入，不能用它证明那次建议正确。

回放不模拟在线队列、丢帧、手机 OCR 调度、后台或显示时延。媒体采样点到建议的间隔排除了计算耗时，不能称作真机响应速度。它证明本轮对这段录像的结构覆盖改善，不证明闪烁、悬浮窗消失或所有开局缺口已解决。

两版全部 35 条有建议记录（含缓存）均核对了选中动作与真实控件的金额和可用状态；104 个错误记录没有残留建议。新版 11 次实际计算、17 次缓存复用。十个成功窗口中六个在首个观察操作帧后 0.5 秒媒体采样点有建议，四个为 1 秒；这里只描述采样位置，不计入真机速度指标。

### QQ 翻后连续建议全下的专项核查

录像三处建议 38.41 的输入保留了开到 2.80、再加到 11.22 全下和后续跟注的完整路径，范围证据随新增过牌从 3 次增至 4、5 次，没有发现遗漏加注或重复计数。主池 37.16 的三名合资格者包含已全下者；38.41 被另一名深筹码跟注后形成两人边池 76.82。若该玩家弃牌，未被跟注的 38.41 退回本人，原全下者仍争主池。

固定真实状态、固定范围及跟注行为的结果符合手算，暂未发现这三帧的状态或结算错误。**这不证明全下是正确策略。** 三处结果的 `statisticallySeparated` 都为 false，翻牌情景首选还不一致；模型只按行动类别更新范围，没有拟合该全下尺寸下真人的持牌分布。不能为避免之前的 QQ 弃牌问题，改成“QQ 必跟”或“QQ 必全下”。

## 冻结策略对照

先以种子 20260916 跑 24 个对照验证流程，再冻结生产源码及工具、使用预先指定的不同种子 20261017 跑正式对照。没有根据正式成绩调整模型。

规则：8 人、每人初始 5000 整数筹码、SB 20／BB 50／UTG 第三盲 100，无抽水和赛事奖金。本人 AI 对比固定 tight-value 脚本，其他座位使用 calling-station、tight-value、pressure 三类简单脚本。这些脚本不调用生产行为模型，不接收其他人的暗牌或未发出的公共牌。完整合成状态与现场识别分开验收。

| 指标 | 实测 |
| --- | ---: |
| 同牌两臂对照 | 192 |
| 独立牌局簇（每副牌 8 个相关轮换） | 24 |
| AI 决策 | 378 |
| 每次完整模拟样本 | 256 |
| 非法动作／计算失败 | 0 |
| 账本不可用而退回随机范围 | 0 |
| AI 相对脚本本人收益差 | +925.6 传统 bb / 100 |
| 按独立牌局簇计算的近似 95% 区间 | −227.6 ～ +2078.8 bb / 100 |

**区间跨零，不能确认优于这组基线。** 它是 24 个独立簇的固定样本正态近似描述，不是有限样本保证。均值很大、区间也很宽，弱脚本的大额错误和全下波动不能外推真人长期收益。没有在看到正结果时提前停止，也没有把失败决策替换成弃牌后计分。

裁判使用生产 Swift 规则和结算，逐手核对筹码守恒；这部分不是独立规则裁判。10 秒故障时限用于完成固定样本，不等于手机在线预算。耗时只用于本地诊断，不作为此轮性能提升依据。

原始合成结果：[192 个对照](benchmarks/2026-09-16-strategy.json)；[冻结配置、源码与二进制哈希](benchmarks/2026-09-16-freeze.json)。这些文件没有真实玩家素材。

```sh
  --pairs 192 --players 8 --samples 256 --seed 20261017 --straddle \

```

## 仍未达到的目标

- 独立强机器人或长期真人对局上的盈利证据。
- 训练并校准过的八人第三盲基础策略、下注尺寸与对手反应模型。
- 对真实人物身份、情绪与下注节奏的可靠归因；画面采样间隔不等于人的思考时间。
- 全部实际操作机会的覆盖、真机端到端时延和长时间 PiP 稳定性。

本轮有实质修复与可复现证据，但还不能把它称为“超级德州 AI”。研究来源及后续路径见 [策略研究](STRATEGY-RESEARCH-2026-09-16.md)和[读取产品复核](SOURCES.md)。
