# 冻结训练候选的完整引擎验收

将第一轮训练选出的 `callOffset=0, aggression=2` 放入真实 `FullHandDecisionEngine` 的本人后续行动策略；对照臂也运行同一个完整引擎，但保留当前 `neutral=0/0.8`。两臂的对手响应假设、公开行动范围模型、筹码规则及可用动作相同，没有把原脚本基准误当成旧版 AI。

**结果只作为研究证据，未更改手机默认模型。** 廉价策略测试中的收益提升不能直接当成完整 AI 提升，更不能当成真人校准。

## 事前固定的配置

候选由训练及验证集选出后冻结，再保存 [配置与源码指纹](../artifacts/training/2026-09-17-full-engine/plan.json)，运行三种预定条件。所有局面 SB/BB=20/50、起始筹码100BB；八人第三盲为 UTG 强制100，无前注、抽水或赛事奖金价值。每次决策完整计算256样本；10秒墙钟上限只用于检测失败，不是手机实时预算。

每个独立发牌都完整轮换底牌及庄位，两臂使用相同发牌和行为随机种子规则。冻结对手为跟注站、紧价值、施压三种弱脚本。两臂各自从公开快照恢复账本及条件范围；它们看到自己的底牌和已发公共牌，不接收其他座位底牌或未来公共牌。

本轮112个新发牌种子与训练全流程的2,496个发牌种子不重合。没有根据本轮得分再次调参或追加有利种子。

## 实测结果

表中的收益差为**候选完整引擎减去 neutral 完整引擎**，不是绝对盈利；区间按独立牌局簇计算，座位轮换不当作独立样本。

| 条件 | 配对轮换 / 独立发牌 | 收益差 BB/100 | 逐条件正态近似95%区间 |
|---|---:|---:|---:|
| 八人第三盲 | 384 / 48 | +639.44 | [+23.71, +1255.17] |
| 六人普通桌 | 192 / 32 | +335.10 | [−251.39, +921.60] |
| 单挑普通桌 | 64 / 32 | −6.25 | [−22.57, +10.07] |

八人结果属于初步正向信号，估计很不稳定；六人和单挑区间跨零。另在 [汇总](../artifacts/training/2026-09-17-full-engine/summary.json) 给出三个预定条件的 Bonferroni 正态近似同时95%区间，八人下界也低于零。小样本、高方差和弱对手意味着不能用这里的巨大 BB/100 数字宣传真人盈利，不能把三个条件的逐条件区间误当总体显著性。

两臂共2,959次完整引擎决策，所有256样本预算完成；非法动作、筹码守恒错误、公开账本回退均为0。独立 Python 审查全部记录，核对29份源码hash、种子隔离、座位轮换、建议与实际合法动作白名单、加注权、金额、新增投入、状态守恒，以及簇均值/标准误/区间，未发现异常。

运行与 Xcode 界面构建等工作有重叠；耗时仅留在原始记录，不能当性能基准。

## 为什么仍不启用

测试没有验证真人分布、具体对手底牌范围、有限手机时限下的决策稳定性，也没有验证新参数在所有筹码深度及人数下通用。训练只拟合本人续打的两个参数，没有训练对手响应模型；此处的完整引擎仍假设三个未校准的对手响应情景。

保留候选、数据和复现工具，默认继续使用原参数。后续需要独立对手家族、更多完整发牌、真实时限，以及有合法完整标签的知情对局记录。只拿最终亮牌手训练会产生选择偏差，不能据此把未亮牌的人都标成弱牌。
