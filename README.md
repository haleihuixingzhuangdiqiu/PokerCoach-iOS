# 牌研 PokerCoach — 面向 WebPcker 的 iOS 全指令版本

**面向 WebPcker（WPK / WePoker）指定海洋牌桌主题的研究项目。不维护；请自行适配、测试和优化。**

通过 iOS 录屏读取自己的公开比赛界面，在紧凑画中画面板同时显示：

> 一个建议动作 + 具体金额 + 独赢估计 + 简短策略理由

“全指令版本”指输出明确的当前行动：弃牌、过牌、跟注多少或加注到多少。它不代替用户点击游戏，也不表示每一种界面或缺失记录都能正确识别。项目用于所有参赛者知情的人机研究房间，与目标游戏无隶属关系。

## 当前能力

| 模块 | 实现 |
| --- | --- |
| iOS 接入 | ReplayKit 录屏扩展、本机帧传输、最新帧队列、过期撤回、单入口首页 |
| 紧凑提示 | 三行 360×104 内容；动作、金额、概率、理由同时存在；不轮播；主操作页无需滚动 |
| 牌桌识别 | 指定八座位主题的本人牌、公共牌、筹码、本街投入、弃牌、全下、庄家、第三盲及实际可用按钮 |
| 多人规则 | 算法支持 2–9 人；普通盲注、单个 UTG live straddle、盲位最后行动选项、完整和短全下、重新开放加注权 |
| 主池与边池 | 按每人累计投入和资格分池，保留弃牌死钱，退回无人跟注部分，处理平分与奇数筹码 |
| 完整策略 | 在完整记录成立时比较真实动作金额，模拟对手响应、再次加注、本人后续行动，以及翻牌、转牌、河牌 |
| 行动范围模型 | 从可唯一重放的公开历史更新每个对手的持牌范围；不重复计算同一截图的行动；无证据时明确使用随机先验 |
| 概率 | 牌型评估、带权范围、联合牌冲突排除、独赢与平局分开、小空间精确枚举及蒙特卡洛抽样 |
| 连续记录 | 从已核对的强制盲注开始记账；跨街保留累计投入；未知字段不补成零；缺失关键动作时撤回完整策略 |

**策略仍是未训练的行为模型和有限次数模拟，未证明长期战胜真人，也不是 GTO 求解器。** 已实现完整规则和逐街模拟，不等于已完成所有真实牌局的连续识别。手机屏幕适配当前仅针对一种八座位布局，算法支持人数更广。

## 本次验证的实际边界

0.1.13 补上本人第三盲标签读取、同街多人被动行动恢复，以及部分私人河牌坚果被错误模拟弃牌的问题。本地完整回归 **329 项通过**。用同一套改正分母的工具重放 240 帧：44 帧识别到本人操作控件，完整建议从 **7 帧增至 28 帧**；连续操作窗口中至少一次有完整建议的从 **3/11 增至 10/11**。这些是观察到的录像帧和窗口，**不是独立手牌数，也不是真机实时成功率**。QQ 的一个翻前窗口仍被飞牌及两帧确认拦住。

另完成 192 个八人第三盲同牌策略对照、378 次 AI 决策，未发生非法动作、计算失败或账本范围回退。但收益差的统计区间跨零，**尚不能确认优于这组弱脚本，更不能证明战胜真人**。完整配置、原始合成结果和限制见 [本轮验收](docs/ACCEPTANCE-2026-09-16.md)。

iOS 0.1.13 已构建并通过签名校验；测试手机当前不可用，此版本还未完成真机连续对局验收。请把它视为待适配的研究源码。

## 第三盲与金额

当前参考桌规为小盲 **0.2**、大盲 **0.5**、UTG 第三盲 **1**，强制投入合计 **1.7**，不是 0.2 前注。翻前名义起注额为 1，翻后最低下注恢复传统大盲 0.5。

内部使用整数筹码：画面 `7.40` 对应 `740`。`raiseTo(740)` 表示本街累计加注到 7.40；若已投入 1，则还需补 6.40。跟注按钮则按“还需投入多少”解读。程序只从已确认可用的实际按钮中选择金额。

详见 [规则与独立 PokerKit 核对](docs/GAME-RULES.md)。不支持把 Mississippi、按钮第三盲、多重 straddle、多次发牌等玩法直接当成本桌规则。

## 构建与运行

需要 macOS、Xcode、Swift 6；生成 Xcode 工程另需 Ruby 的 `xcodeproj` gem。Swift 算法包没有第三方库依赖。视频工具需本机 `ffmpeg` / `ffprobe`。

```sh
swift test -c release
swift run -c release poker-coach equity AsKs Js8s5d AcJc
swift run -c release poker-coach analyze fixtures/six-player-flop.json
swift run -c release poker-coach benchmark
swift run -c release poker-video /path/to/recording.mp4
swift run -c release poker-cards /path/to/frame.png
swift run -c release poker-screen /path/to/frame.png
```

安装自己的 iOS 版本：

```sh
gem install xcodeproj
POKER_DEVELOPMENT_TEAM=YOUR_TEAM_ID \
POKER_BUNDLE_ID=your.unique.pokercoach \
ruby iOS/generate_project.rb
open iOS/PokerCoach.xcodeproj
```

在 Xcode 中选择自己的开发团队和手机，构建运行。主 App 与录屏扩展需要使用同一团队并正确签名。打开牌研，点击开始，在系统录屏面板选择牌研录屏。画中画由 iOS 管理，最终大小、位置及生命周期受系统控制。

仓库不携带个人签名、设备信息、开发者证书、原始录像或手机运行日志。依赖私有录像帧的回归测试会在素材缺失时跳过；跳过不代表通过。准备自己的素材、修改识别区域并重新验证，见 [自行适配与复验](docs/PUBLIC-REPOSITORY.md)。

## 策略路径

1. **完整记录路径**：已确认强制盲注 → 连续合法动作与筹码核对 → 对手范围更新 → 多人逐街模拟 → 按模拟期望收益选择一个动作。
2. **单次开池重建**：翻前全部筹码、投入、弃牌、行动者、庄家和桌规一致，且所有合法解释都指向同一次开池时，连续两帧确认当前完整状态，接入同一多人逐街模拟。单独标注来源，`historyComplete=false`。
3. **局部快照路径**：多人待响应或投入未知时只保留条件概率、确实可用的免费过牌；不能用“当前底池 + 本人跟注”乘多人摊牌权益生成跟弃建议。真实单挑、非封顶且未识别到全下时才保留受限比较。

显示的百分数是**给定持牌范围下，大家留到摊牌时本人独赢的估计**，不是当前动作的盈利概率。策略选择使用后续筹码收益，考虑他人弃牌、跟注和再加注，因此不能只按胜率高低下注。抽样误差与对手模型误差是不同问题。

完整模型、预算、动作限制和测试设计见 [多人逐街策略](docs/FULL-HAND-STRATEGY.md)；已知错误的根因和独立概率核验见 [系统性审计](docs/SYSTEMIC-AUDIT.md)。

## 尚未完成

- 所有牌桌主题、分辨率、遮挡及动画的通用识别。
- 除满足严格条件的单次开池外，漏掉中间动作后仍可保证恢复完整加注权和边池资格。
- 全链路指引覆盖率仍有明显缺口；单元测试通过不能证明实际每手都有建议。
- 经过真人数据校准的持牌范围、具体下注尺寸、人物身份、心理或节奏模型。
- 训练完成的多人基础策略、GTO 保证、独立长期对局盈利验证。
- 抽水、赛事奖金价值 / ICM、特殊奖励与多次发牌。
- 持续真实对局的全链路覆盖率、耗电、热量和所有 PiP 消失原因的验收。
